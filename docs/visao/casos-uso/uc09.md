# UC09 - Gerenciar Tipos de Denúncias

[Voltar para Casos de Uso](../backlog.md#9-casos-de-uso)

## 1. Atores

**Atores principais:** Administrador

## 2. Objetivo

Permitir que administradores criem, visualizem, editem e excluam categorias de denúncias utilizadas pelos usuários durante o registro de denúncias.

## 3. Pré-condições

1. O ator deve estar autenticado no aplicativo.
2. O ator deve possuir perfil de administrador.
3. O ator deve acessar a página de gerenciamento de categorias de denúncias.
4. O sistema deve possuir conexão ativa com o backend.
5. O backend deve estar integrado ao banco de dados Firebase/Firestore.

## 4. Fluxo Principal

**FP01 - Criar Categoria de Denúncia**

1. O administrador acessa a página de gerenciamento de categorias de denúncias. ([RF32](#uc09-rf32))
2. O sistema identifica o administrador autenticado. ([RF32](#uc09-rf32))
3. O sistema apresenta a lista de categorias cadastradas e a opção de criar uma nova categoria. ([RF32](#uc09-rf32))
4. O administrador seleciona a opção de criar categoria. ([RF30](#uc09-rf30))
5. O sistema apresenta o formulário de cadastro da categoria. ([RF30](#uc09-rf30))
6. O administrador informa o nome da categoria e, opcionalmente, uma descrição. ([RF30](#uc09-rf30))
7. O administrador confirma o cadastro. ([RF30](#uc09-rf30))
8. O sistema valida as informações fornecidas. ([RF30](#uc09-rf30))
9. O sistema registra a categoria no banco de dados. ([RF30](#uc09-rf30))
10. O sistema atualiza a lista de categorias. ([RF30](#uc09-rf30), [RF32](#uc09-rf32))
11. O sistema exibe mensagem de sucesso informando que a categoria foi criada. ([RF30](#uc09-rf30))

## 5. Fluxos Alternativos

**FA01 - Listar Categorias**

1. O administrador acessa a página de gerenciamento de categorias. ([RF32](#uc09-rf32))
2. O sistema busca as categorias cadastradas. ([RF32](#uc09-rf32))
3. O sistema exibe a lista de categorias disponíveis. ([RF32](#uc09-rf32))
4. O administrador visualiza as categorias cadastradas. ([RF32](#uc09-rf32))

**FA02 - Editar Categoria**

1. O administrador seleciona uma categoria existente. ([RF31](#uc09-rf31))
2. O administrador aciona a opção de edição. ([RF31](#uc09-rf31))
3. O sistema carrega as informações atuais da categoria. ([RF31](#uc09-rf31))
4. O administrador altera os dados desejados. ([RF31](#uc09-rf31))
5. O administrador confirma a alteração. ([RF31](#uc09-rf31))
6. O sistema valida as informações fornecidas. ([RF31](#uc09-rf31))
7. O sistema atualiza a categoria no banco de dados. ([RF31](#uc09-rf31))
8. O sistema exibe mensagem de sucesso informando que a categoria foi atualizada. ([RF31](#uc09-rf31))

**FA03 - Excluir Categoria**

1. O administrador seleciona uma categoria existente. ([RF33](#uc09-rf33))
2. O administrador aciona a opção de exclusão. ([RF33](#uc09-rf33))
3. O sistema solicita confirmação da operação. ([RF33](#uc09-rf33))
4. O administrador confirma a exclusão. ([RF33](#uc09-rf33))
5. O sistema remove ou inativa a categoria, conforme a existência de denúncias vinculadas. ([RF33](#uc09-rf33))
6. O sistema atualiza a lista de categorias. ([RF33](#uc09-rf33), [RF32](#uc09-rf32))
7. O sistema exibe mensagem de sucesso informando que a categoria foi removida. ([RF33](#uc09-rf33))

**FA04 - Cancelar Operação**

1. Durante a criação ou edição de uma categoria, o administrador seleciona a opção de cancelar ou voltar. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))
2. O sistema descarta as alterações não salvas. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))
3. O sistema retorna para a tela anterior. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))
4. Nenhuma alteração é realizada no banco de dados. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))

## 6. Fluxos de Exceção

**FE01 - Categoria Duplicada**

1. O administrador informa o nome de uma categoria já existente. ([RF30](#uc09-rf30))
2. O sistema verifica as categorias cadastradas. ([RF30](#uc09-rf30))
3. O sistema identifica a duplicidade. ([RF30](#uc09-rf30))
4. O sistema impede o cadastro da categoria. ([RF30](#uc09-rf30))
5. O sistema informa que já existe uma categoria com esse nome. ([RF30](#uc09-rf30))

**FE02 - Campo Obrigatório Não Preenchido**

1. O administrador tenta criar ou editar uma categoria sem informar o nome. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))
2. O sistema identifica a ausência do campo obrigatório. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))
3. O sistema impede o salvamento. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))
4. O sistema destaca o campo obrigatório. ([RF30](#uc09-rf30), [RF31](#uc09-rf31))

**FE03 - Categoria Indisponível**

1. O administrador tenta editar ou excluir uma categoria. ([RF31](#uc09-rf31), [RF33](#uc09-rf33))
2. O sistema verifica a existência da categoria. ([RF31](#uc09-rf31), [RF33](#uc09-rf33))
3. O sistema identifica que a categoria foi removida ou tornou-se indisponível. ([RF31](#uc09-rf31), [RF33](#uc09-rf33))
4. O sistema impede a operação. ([RF31](#uc09-rf31), [RF33](#uc09-rf33))
5. O sistema atualiza a listagem de categorias. ([RF32](#uc09-rf32))

**FE04 - Usuário Sem Permissão**

1. Um usuário sem perfil de administrador tenta acessar o gerenciamento de categorias. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
2. O sistema identifica a ausência de permissões administrativas. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
3. O sistema bloqueia o acesso à funcionalidade. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
4. O sistema informa que o acesso é restrito a administradores. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))

**FE05 - Falha de Conectividade**

1. O administrador tenta executar uma operação sem conexão com o backend. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
2. O sistema não consegue concluir a operação. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
3. O sistema exibe mensagem de falha de conexão. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
4. O sistema orienta o administrador a tentar novamente quando a conexão for restabelecida. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))

**FE06 - Erro Interno no Banco de Dados**

1. O administrador confirma uma operação válida envolvendo categorias de denúncias. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
2. O sistema tenta registrar, atualizar, excluir ou consultar dados no Firestore. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
3. O banco de dados retorna erro ou indisponibilidade. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
4. O sistema cancela a operação. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
5. O sistema exibe mensagem de erro interno. ([RF30](#uc09-rf30), [RF31](#uc09-rf31), [RF32](#uc09-rf32), [RF33](#uc09-rf33))
